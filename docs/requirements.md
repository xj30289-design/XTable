## 3. 产品定位

XTable 是一款面向游戏开发团队的桌面配置表编辑器，主要服务策划与程序共同维护游戏配置数据的工作场景。

MVP 版本采用“项目资源管理器 + 表格编辑工作台”的产品形态，兼容 Excel/CSV，重点提升日常改表效率、降低配置错误，并提供完整的本地日志系统与数据异常检测系统。

默认技术路线为 Python + PySide6/Qt + Qt Model/View。该技术路线记录于 [开发计划](./development-plan.md)，后续如需调整，必须同步更新开发计划和开发日志。

## 4. MVP 目标

- 让策划能以接近 Excel 的方式快速编辑配置表。
- 让程序能通过字段规则、引用关系和校验结果约束配置数据质量。
- 在导入、编辑、保存、导出过程中尽早发现数据异常。
- 通过日志和诊断信息帮助团队追踪问题、复现问题、定位责任边界。
- 以本地文件项目为基础，适配 Git、SVN、Perforce 等版本管理工具。

## 5. 非目标范围

MVP 不包含以下能力：

- 实时多人协作。
- 账号体系、权限体系、云同步。
- 内置审核流、发布流、线上热更新管线。
- JSON、Lua、Protobuf 等运行时格式导出。
- 用户自定义脚本规则或插件系统。
- AI 自动生成配置内容。

## 6. 用户与场景

### 6.1 目标用户

- 数值策划：维护角色、技能、道具、成长、掉落等大量数值配置。
- 系统策划：维护任务、活动、玩法规则、条件表达等系统配置。
- 技术策划：协助定义字段类型、枚举、跨表引用和校验规则。
- 程序：定义配置表结构约束，检查数据是否满足客户端或服务端消费要求。

### 6.2 核心场景

- 策划打开本地项目，在资源管理器中定位某张配置表并进行日常修改。
- 策划批量复制、填充、筛选、替换配置内容，减少重复录入。
- 程序为字段设置类型、枚举、唯一性、范围、引用关系等规则。
- 编辑器在编辑、保存、导出前提示重复 ID、空引用、枚举越界等问题。
- 团队成员通过日志和异常报告定位一次错误配置的来源和影响范围。

## 7. 功能模块总览

### 7.1 UI 与交互模块

主界面由顶部工具栏、中间操作区和底部状态栏组成。

- 顶部工具栏提供新建、导入、导出、保存、校验、撤销、重做、主题切换等常用入口。
- 中间操作区包含左侧功能侧边栏和右侧功能窗口。
- 功能侧边栏至少包含 Table、Enum、Meta 三个主标签。
- 底部状态栏展示当前项目、当前表、选中区域、校验状态、保存状态、后台任务进度、错误和警告数量。

UI 模块统一提供：

- 功能窗口。
- 消息提示弹窗。
- 信息收集弹窗。
- 图标按钮和文本按钮。
- 面板与抽屉。
- 列表、树、表格、表单、标签页、搜索框、筛选器、下拉框等基础组件。

编辑器必须支持 Dark 和 Light 两套主题。所有可见 UI 颜色必须来自统一主题变量，业务模块不得硬编码颜色。

### 7.2 项目与文件模块

项目模块负责本地配置项目的创建、打开、保存和文件安全。

项目级基本信息包括：

- 项目名。
- 根目录。
- 操作者名称。
- 默认编码。
- 日志保留天数。
- 主题偏好。
- 最近打开记录。

文件安全要求：

- 打开文件失败时提示原因和建议处理方式。
- 保存时检测目标文件是否被占用、只读或被外部修改。
- 文件在编辑期间被外部修改时提示刷新、另存或放弃外部变化。
- 保存冲突必须阻止静默覆盖。
- 临时文件和恢复文件不得污染正式导出目录。

### 7.3 数据编辑模块

数据编辑模块负责配置表数据的基础编辑和高频操作。

MVP 支持：

- 单元格编辑。
- 插入、删除、复制行。
- 插入、删除、复制列。
- 多选区域批量赋值。
- 拖拽填充连续值或复制值。
- 跨表复制粘贴。
- 从外部 Excel/CSV 粘贴数据。
- 按字段筛选。
- 单字段或多字段排序。
- 全表查找。
- 当前表查找替换。
- 选中区域查找替换。
- 撤销和重做。

表格类型和字段类型的详细行为见：

- [表格类型规格](./specs/table-types.md)
- [字段类型规格](./specs/field-types.md)

### 7.4 数据导入导出模块

MVP 支持导入：

- Excel 文件。
- CSV 文件。
- 一次导入多张表。

导入时需要识别：

- 表名。
- 表格类型。
- 表头。
- 字段名。
- 字段类型。
- 数据行。

MVP 支持导出：

- 当前表导出为 Excel/CSV。
- 整个项目导出为 Excel/CSV。
- 按表格类型执行专属导出逻辑。
- 面向程序的规则与类型定义导出接口。

导出前必须自动触发数据异常检测。存在 Error 级问题时禁止导出；仅存在 Warn 级问题时，用户确认后可继续导出。

### 7.5 规则与校验模块

规则与校验模块负责在导入、编辑、保存和导出过程中发现数据质量问题。

MVP 支持：

- 字段类型校验。
- 必填校验。
- 唯一校验。
- 数值范围校验。
- 枚举值校验。
- 跨表引用校验。
- 主键校验。
- 特征键校验。
- 列表字段校验。
- Meta 字段校验。
- Json 字段语法和内容校验。
- 表格类型结构校验。

校验结果统一结构、严重级别、导出阻塞规则和问题定位要求见 [校验规则规格](./specs/validation-rules.md)。

### 7.6 数据异常检测系统

数据异常检测系统负责把校验结果转换为可定位、可筛选、可导出的异常报告。

检测时机：

- 导入后。
- 单元格编辑后。
- 保存前。
- 导出前。
- 用户手动触发校验时。

异常报告视图需要支持：

- 按严重级别、表、表格类型、字段、字段类型、规则类型筛选。
- 按关键词搜索。
- 点击异常项跳转到源单元格。
- 展示问题原因和建议修复方式。
- 复制或导出异常摘要。

### 7.7 日志系统

日志系统用于记录用户操作、系统状态、数据变更和异常诊断信息，帮助团队追踪配置修改历史、定位工具问题和复现异常场景。

日志类型：

- 用户操作日志。
- 系统日志。
- 数据变更日志。
- 异常日志。

日志级别：

- Debug。
- Info。
- Warn。
- Error。
- Fatal。

日志面板需要支持按时间、级别、模块、日志类型和关键词筛选。关键错误需要生成可复制诊断信息，至少包含应用版本、操作系统、项目路径、当前表、操作者、会话 ID、错误时间、错误摘要、相关日志片段和异常堆栈。

### 7.8 权限与协作边界模块

MVP 不实现：

- 登录账号。
- 角色权限。
- 实时多人编辑。
- 云端同步。
- 内置审批流程。
- 发布审批状态。

MVP 支持设置本地操作者名称。操作者名称用于用户操作日志和数据变更日志。未设置时使用系统用户名或默认名称。

协作风险检测需要覆盖：

- 文件被外部修改。
- 文件保存冲突。
- 只读文件。
- 文件被占用。
- 版本工具锁定状态。

## 8. 非功能需求

### 8.1 易用性

- 普通策划应能在 30 分钟内完成打开项目、定位表、编辑、校验、导出的基础流程。
- 高频功能需要有快捷键或明显入口。
- 错误提示必须使用业务可理解语言，避免只展示技术异常。
- Table、Enum、Meta 上下文切换必须直观稳定。
- 新建、导入、导出等信息收集弹窗必须清晰展示必填项、默认值、校验错误和确认结果。

### 8.2 性能

- 打开中等规模项目时应有加载进度反馈。
- 大表滚动、选择、编辑不应出现明显卡顿。
- 校验耗时超过 1 秒时需要展示进度或状态。
- 导入、导出、整项目校验需要记录耗时日志。

### 8.3 稳定性

- 文件读写失败不得导致应用崩溃。
- 单张表解析失败不得阻止用户查看其他可用表。
- 批量操作失败时需要说明已完成和未完成范围。
- 异常退出后应尽量提供恢复未保存内容的能力。

### 8.4 可维护性

- UI、项目文件、数据编辑、导入导出、规则校验、异常检测、日志系统应按模块解耦。
- 所有可见 UI 组件、弹窗、按钮、面板、状态提示和主题适配应由 UI 模块统一提供。
- 校验规则需要有统一结果结构。
- 日志接口需要统一，避免各模块自行拼接不一致日志。
- 表格类型和字段类型必须通过统一扩展接口接入。

## 9. 验收标准

### 9.1 项目与导入验收

- 用户能创建并打开本地配置项目。
- 用户能导入包含多张配置表的 Excel/CSV 文件。
- 导入后能在项目资源管理器中浏览、搜索、切换配置表。
- 导入异常能生成结构异常报告。

### 9.2 UI 与主题验收

- 主界面包含顶部工具栏、中间操作区、底部状态栏。
- 中间操作区最左侧为功能侧边栏，至少包含 Table、Enum、Meta。
- 点击 Table、Enum、Meta 时，右侧功能窗口切换到对应界面。
- 底部状态栏能展示当前项目、当前对象、保存状态、校验状态、后台任务和问题数量。
- 问题按钮能展开和收起底部问题报告抽屉。
- 编辑器能在 Dark 和 Light 主题之间切换，切换后所有可见 UI 立即刷新。

### 9.3 编辑验收

- 用户能完成单元格编辑、多选区域编辑、复制粘贴、拖拽填充。
- 用户能插入和删除行列。
- 用户能使用筛选、排序、查找替换、批量编辑。
- 用户能撤销和重做编辑操作。
- 用户能创建或打开普通表、分组表、二维表。
- 用户能为 Table 设置主键和特征键。
- 用户能创建枚举、Meta、列表字段和 Json 字段。
- 用户能打开 Json 专用编辑器，完成 Json 编辑、格式化、压缩和错误定位。

### 9.4 校验与异常检测验收

- 系统能检测字段类型错误、必填为空、唯一字段重复、主键缺失或重复。
- 系统能检测数值范围越界、枚举越界、跨表引用不存在。
- 系统能检测分组表缺少 `groupKey`、空 `groupKey`、无法归组数据。
- 系统能检测二维表缺少轴字段、重复坐标、缺失坐标、坐标越界。
- 系统能检测列表字段元素类型错误、空元素、长度越界、嵌套深度越界。
- 系统能检测 Meta 子字段缺失、类型错误和必填为空。
- 系统能检测 Json 语法错误、必需键缺失、禁止键存在、值类型不匹配和嵌套深度越界。
- 异常报告能定位到表、字段、行、单元格。
- Json 异常报告能定位到 Json 路径，并打开 Json 编辑器定位问题。
- 异常报告能说明问题原因和建议修复方式。

### 9.5 导出验收

- 用户能导出当前表为 Excel/CSV。
- 用户能导出整个项目为 Excel/CSV。
- 分组表导出后能按 group 划分区间并保留 group 边界。
- 二维表导出后能按 x 轴和 y 轴还原为矩阵结构。
- 列表字段、Meta 字段和 Json 字段能导出为稳定、可解析的表达。
- 程序侧能通过独立导出接口获取全局枚举、Meta、字段类型、表结构和校验规则定义。
- 导出前会自动执行异常检测。
- 存在 Error 级问题时禁止导出。
- 仅存在 Warn 级问题时，用户确认后可继续导出。

### 9.6 日志验收

- 系统能记录打开项目、导入、编辑、批量修改、校验、导出、保存、撤销、重做。
- 系统能记录启动、关闭、文件读写、解析失败、性能耗时、异常堆栈。
- 系统能记录数据变更的表、行、字段、旧值、新值、时间、操作者、会话 ID。
- UI 日志面板能按时间、级别、模块、类型和关键词筛选。
- 关键错误能生成可复制诊断信息。
- 日志能按保留策略滚动和清理。

### 9.7 版本工具友好验收

- 项目规则和配置文件可被版本工具追踪。
- 日志、缓存、临时恢复文件可被版本工具忽略。
- 修改单张表时不应导致大量无关文件变化。
- 外部文件变更、只读、占用、保存冲突能被检测并提示。

## 10. 推荐项目目录约定

```text
xtable-project/
  tables/              # 表数据
  rules/               # 字段规则、引用关系
  enums/               # 项目全局枚举定义
  types/               # 自定义数据元和字段类型定义
  settings/            # 项目设置和本地偏好
  logs/                # 本地日志，建议版本工具忽略
  cache/               # 缓存，建议版本工具忽略
  recovery/            # 异常恢复数据，建议版本工具忽略
```

推荐忽略：

```text
logs/
cache/
recovery/
*.tmp
*.lock
```

## 11. 默认假设

- MVP 以 Excel/CSV 为主要输入输出格式。
- MVP 支持普通表、分组表、二维表三类表格类型。
- MVP 支持全局枚举、Meta、列表字段和 Json 字段。
- MVP UI 完整支持 Dark 和 Light 两套主题。
- 面向程序的导出接口用于导出元数据和类型定义，不改变 Excel/CSV 作为数据主体导入导出的边界。
- 完整日志系统在第一版定义为本地日志。
- 数据异常检测系统是内置校验与诊断能力，不要求第一版支持用户自定义脚本规则。
- 第一版优先本地桌面工作流，不引入服务器依赖。
- 当前需求文档作为新项目主 PRD，详细规格由独立规格文档承载。
