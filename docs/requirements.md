# XTable 游戏配置表编辑器 MVP 需求文档

## 1. 文档概述

### 1.1 产品定位

XTable 是一款面向游戏开发团队的桌面配置表编辑器，主要服务策划与程序共同维护游戏配置数据的工作场景。MVP 版本采用“项目资源管理器 + 表格编辑工作台”的产品形态，兼容 Excel/CSV，重点提升日常改表效率、降低配置错误，并提供完整的本地日志系统与数据异常检测系统。

### 1.2 MVP 目标

- 让策划能以接近 Excel 的方式快速编辑配置表。
- 让程序能通过字段规则、引用关系和校验结果约束配置数据质量。
- 在导入、编辑、保存、导出过程中尽早发现数据异常。
- 通过日志和诊断信息帮助团队追踪问题、复现问题、定位责任边界。
- 以本地文件项目为基础，适配 Git、SVN、Perforce 等版本管理工具。

### 1.3 非目标范围

MVP 不包含以下能力：

- 实时多人协作。
- 账号体系、权限体系、云同步。
- 内置审核流、发布流、线上热更新管线。
- JSON、Lua、Protobuf 等运行时格式导出。
- 用户自定义脚本规则或插件系统。
- AI 自动生成配置内容。

## 2. 用户与场景

### 2.1 目标用户

- 数值策划：维护角色、技能、道具、成长、掉落等大量数值配置。
- 系统策划：维护任务、活动、玩法规则、条件表达等系统配置。
- 技术策划：协助定义字段类型、枚举、跨表引用和校验规则。
- 程序：定义配置表结构约束，检查数据是否满足客户端或服务端消费要求。

### 2.2 核心场景

- 策划打开本地项目，在资源管理器中定位某张配置表并进行日常修改。
- 策划批量复制、填充、筛选、替换配置内容，减少重复录入。
- 程序为字段设置类型、枚举、唯一性、范围、引用关系等规则。
- 编辑器在编辑、保存、导出前提示重复 ID、空引用、枚举越界等问题。
- 团队成员通过日志和异常报告定位一次错误配置的来源和影响范围。

## 3. 功能模块

### 3.1 UI 与交互模块

#### 3.1.1 主界面布局

主界面由三个主要层级组成：

- 中间操作区：承载编辑器的主要功能窗口，是用户编辑 Table、Enum、Meta 等核心对象的主要区域。
- 顶部工具栏：承载常用操作入口，例如新建、导入、导出、保存、校验、撤销、重做、主题切换等。
- 底部状态栏：展示当前项目、当前表、选中区域、校验状态、保存状态、后台任务进度、错误和警告数量等状态信息。

中间操作区由两个区域组成：

- 功能侧边栏：位于操作区最左侧，以标签形式展示主要功能类型。
- 功能窗口：位于功能侧边栏右侧，根据当前选中的侧边栏标签展示对应功能界面。

功能侧边栏至少包含以下主标签：

- Table：配置表管理与表格编辑。
- Enum：项目全局枚举管理。
- Meta：自定义数据元管理。

功能侧边栏标签用于控制操作区主要功能窗口的显示。切换标签时，功能窗口需要切换到对应模块，并保留各模块的基础上下文，例如最近打开的表、当前枚举类型、当前数据元类型。

Table 功能窗口需要支持：

- 配置表资源管理。
- 表格编辑区。
- 字段属性与规则面板。
- 问题摘要入口，用于打开底部问题报告抽屉。

Enum 功能窗口需要支持：

- 全局枚举类型列表。
- 枚举项编辑。
- 枚举引用影响查看。

Meta 功能窗口需要支持：

- 自定义数据元列表。
- 数据元子字段编辑。
- 数据元引用关系查看。
- 数据元结构复杂度提示。
- Meta 升级为 Table 的操作入口。

#### 3.1.2 资源导航

- Table 功能窗口中支持按目录组织配置表。
- Table 功能窗口中支持按模块或标签筛选配置表。
- Table 功能窗口中支持配置表搜索。
- Table 功能窗口中支持最近打开表记录。
- Table 功能窗口中支持标记常用表，便于大型项目快速定位。

#### 3.1.3 UI 能力范围

编辑器中所有可见 UI 功能都应由 UI 模块统一支持。UI 模块需要覆盖不同定位的 UI 显示能力，并为业务模块提供一致的组件、主题、交互和状态反馈基础。

UI 模块至少支持以下 UI 类型：

- 功能窗口：组成中间操作区的主要业务界面，例如 Table、Enum、Meta。
- 消息提示弹窗：展示错误、警告、确认、成功提示、不可恢复异常等短流程反馈。
- 信息收集弹窗：用于新建、导入、导出、创建枚举、创建数据元、配置字段规则等需要用户输入的流程。
- 图标按钮：用于工具栏、侧边栏、表格操作、快捷命令等紧凑操作入口。
- 文本按钮：用于弹窗确认、取消、应用、重试、查看详情等明确文本操作。
- 面板与抽屉：用于属性、规则、引用、异常详情等辅助信息展示。
- 列表、树、表格、表单、标签页、搜索框、筛选器、下拉框等基础组件。

UI 模块需要统一管理：

- 组件状态，包括默认、悬停、按下、禁用、选中、加载中、错误。
- 弹窗层级和焦点管理。
- 快捷键提示和键盘导航。
- 空状态、加载状态、错误状态。
- 长任务进度反馈。
- 组件尺寸、间距、图标、颜色和字体规范。
- 简洁高效的过渡动画，包括窗口切换、抽屉展开收起、弹窗出现关闭、按钮状态变化、列表展开折叠、主题切换刷新等。

过渡动画需要遵守：

- 项目整体动画风格统一，不同组件不能各自使用割裂的动效风格。
- 动画应短促、清晰、服务操作反馈，不影响高频编辑效率。
- 长列表、表格滚动、批量编辑、键盘导航等高频操作不得因动画产生明显延迟。
- Dark 和 Light 两套主题下的动画状态都需要保持视觉一致。

#### 3.1.4 主题系统

编辑器整体需要支持 Dark 和 Light 两套主题。所有 UI 显示都必须适配两套主题，包括主窗口、功能侧边栏、功能窗口、顶部工具栏、底部状态栏、弹窗、按钮、表格、表单、图标、日志、异常报告和状态提示。

主题系统需要满足：

- 用户可在编辑器内切换 Dark 或 Light 主题。
- 切换主题时当前窗口立即刷新，不需要重启应用。
- 所有组件颜色来自统一主题变量，不允许业务模块硬编码颜色。
- 错误、警告、成功、信息、选中、禁用等语义颜色在两套主题下都要保持可读。
- 表格网格线、选中单元格、异常标记、只读状态、引用状态在两套主题下都要清晰可辨。
- 图标按钮和文本按钮在两套主题下都需要有明确的默认、悬停、按下、禁用和选中状态。
- 主题选择应保存到用户配置，下次打开项目时恢复。

#### 3.1.5 表格交互

- 支持单元格、整行、整列、多区域选择。
- 支持键盘方向键、Tab、Enter 快速移动焦点。
- 支持复制、粘贴、剪切、撤销、重做快捷键。
- 支持筛选、排序、查找替换、批量编辑入口。
- 支持通过颜色、图标或标记展示错误、警告、只读、引用字段等状态。

#### 3.1.6 问题定位

- 单元格异常需要在表格内直接可见。
- 问题面板中的异常项点击后跳转到对应表、行、字段、单元格。
- 右侧面板展示当前单元格的字段说明、字段规则、引用目标和错误原因。
- 跨表引用问题需要能从源单元格跳转到目标表或缺失目标说明。
- 问题报告窗口采用底部抽屉式界面，从主界面底部弹出或收回。
- 底部状态栏需要提供问题按钮，用户点击后可展开或收起问题报告抽屉。
- 发生高风险问题时，问题报告抽屉可以自动弹出，并聚焦到对应问题。
- 问题报告抽屉收起后，底部状态栏仍需展示错误、警告和提示数量。

### 3.2 项目与文件模块

#### 3.2.1 项目管理

- 支持创建本地配置项目。
- 支持打开已有本地配置项目。
- 支持保存项目配置、表数据、规则配置和用户偏好。
- 支持最近项目列表。
- 支持项目级基本信息：项目名、根目录、操作者名称、默认编码、日志保留天数。

#### 3.2.2 文件组织

项目文件需要按用途拆分，避免所有内容混在单个不可读文件中：

- 表数据文件：保存 Excel/CSV 来源数据或编辑后的表数据。
- 表结构与规则文件：保存表格类型、字段类型、自定义数据元、枚举、引用、范围、必填、唯一等规则。
- 用户配置文件：保存本地操作者名称、界面偏好、最近打开记录。
- 日志文件：保存操作日志、系统日志、数据变更日志和异常日志。
- 临时恢复文件：保存未正常退出时的编辑恢复信息。

#### 3.2.3 文件安全

- 打开文件失败时，需要提示原因和建议处理方式。
- 保存时需要检测目标文件是否被占用、只读或被外部修改。
- 如果文件在编辑期间被外部修改，需要提示用户刷新、另存或放弃外部变化。
- 保存冲突必须阻止静默覆盖。
- 临时文件和恢复文件不得污染正式导出目录。

#### 3.2.4 版本工具友好

- 项目配置和规则文件应尽量使用文本格式，方便版本差异比较。
- 日志、缓存、临时恢复文件应与正式数据分离，便于加入忽略规则。
- 表数据变更应避免产生无意义格式变化。
- 需要在文档中提供推荐忽略项，例如日志目录、缓存目录、临时恢复目录。

### 3.3 数据编辑模块

#### 3.3.1 基础编辑

- 支持单元格编辑。
- 支持插入、删除、复制行。
- 支持插入、删除、复制列。
- 支持多选区域批量赋值。
- 支持拖拽填充连续值或复制值。
- 支持跨表复制粘贴。
- 支持从外部 Excel/CSV 粘贴数据。

#### 3.3.2 高频编辑能力

- 支持按字段筛选。
- 支持单字段或多字段排序。
- 支持全表查找。
- 支持当前表查找替换。
- 支持选中区域查找替换。
- 支持批量修改选中单元格。
- 支持常用快捷键，并在菜单中展示快捷键提示。

#### 3.3.3 字段类型

MVP 支持以下字段类型：

- 字符串。
- 整数。
- 浮点数。
- 布尔值。
- 枚举。
- ID。
- 引用字段。
- 列表字段。
- 自定义数据元字段。

字段可配置以下属性：

- 字段名。
- 显示名。
- 字段说明。
- 默认值。
- 是否必填。
- 是否唯一。
- 是否只读。
- 数值范围。
- 枚举候选值。
- 引用目标表和目标字段。
- 列表元素类型。
- 自定义数据元类型。

列表字段用于表达同一字段内的多值配置，可以嵌套基础类型、枚举、引用字段或自定义数据元。列表字段需要支持元素新增、删除、排序、复制、粘贴，并能对列表长度、元素类型、元素唯一性和空元素进行校验。

自定义数据元用于表达可复用的复合数据结构。它类似一张表的骨架，用于快速组合少量结构化字段，并能作为字段类型或列表元素类型被其他表复用。

自定义数据元定义至少包含：

- 数据元类型标识。
- 类型显示名。
- 类型说明。
- 子字段列表。
- 子字段类型。
- 子字段默认值。
- 子字段校验规则。
- 面向程序的导出字段名。

自定义数据元适合简单组合型数据。当数据元结构过于复杂、嵌套过深、引用关系过多，或单个数据元实例数量过大时，编辑器应提示用户考虑将其升级为独立配置表。

自定义数据元和列表字段需要支持嵌套，但 MVP 应限制最大嵌套深度，避免编辑体验、校验性能和导出结构失控。

Meta 需要支持升级为 Table。升级时编辑器应基于数据元结构创建对应配置表，自动补全相关表引用，并将原本引用该 Meta 的字段类型替换为引用新 Table 的引用字段。升级过程需要提供变更预览、冲突提示和可回退方案。

#### 3.3.4 表格类型

除普通数据表外，MVP 需要支持可扩展的表格类型体系。每张表必须声明表格类型，编辑器根据表格类型决定编辑视图、结构规则、校验规则和导出行为。

MVP 支持以下表格类型：

- 普通表：默认表格类型，以行为记录、列为字段，适合道具、技能、任务、怪物、掉落等常规配置。
- 分组表：在普通表基础上指定 `groupKey` 字段，表内数据按 `groupKey` 划分为多个 group；导出时需要按 group 划分区间，并保持同一 group 的数据连续或提供明确的分组边界。
- 二维表：指定两个轴字段或轴范围 `x`、`y`，配置 `x * y` 个值，适合成长曲线、等级参数、二维映射、坐标或矩阵类配置。

表格类型配置至少包含：

- 表格类型标识。
- 类型显示名。
- 类型说明。
- 类型专属参数。
- 类型专属校验规则。
- 类型专属导出规则。

普通表专属参数：

- 主键字段。
- 特征键字段。
- 默认排序字段。

Table 可以设置主键和特征键：

- 主键作为该表被其他表引用时保存和导出的实际值。
- 特征键作为该表被引用时的特征预览，用于在引用字段、问题报告、搜索结果、提示弹窗中帮助用户识别引用对象。
- 主键必须唯一且稳定；特征键可以由一个或多个字段组成，但不应替代主键参与引用存储。

分组表专属参数：

- `groupKey` 字段。
- group 排序规则。
- group 内排序规则。
- 导出时 group 边界表达方式。

二维表专属参数：

- x 轴字段或 x 轴范围。
- y 轴字段或 y 轴范围。
- 值字段。
- 缺失坐标默认值策略。
- 坐标重复处理策略。

后续新增表格类型时，必须遵守统一的表格类型接口：声明类型元数据、编辑视图能力、结构校验规则、内容校验规则、导入解析规则、导出规则和日志事件，不允许把新类型逻辑散落在 UI 或导出流程中。

#### 3.3.5 撤销与恢复

- 编辑行为必须支持撤销和重做。
- 批量编辑作为单次操作进入撤销栈。
- 导入、删除表、删除大量数据等高风险操作需要二次确认。
- 程序异常退出后，重新打开项目时应提示是否恢复未保存编辑状态。

### 3.4 数据导入导出模块

#### 3.4.1 导入能力

- 支持导入 Excel 文件。
- 支持导入 CSV 文件。
- 支持一次导入多张表。
- 导入时识别表名、表格类型、表头、字段名、字段类型和数据行。
- 导入普通表时按标准行列结构解析。
- 导入分组表时识别 `groupKey` 字段，并检查 group 数据是否可被稳定划分。
- 导入二维表时识别 x 轴、y 轴和值字段或轴范围，并转换为统一的二维表内部结构。
- 导入完成后生成结构异常报告。

#### 3.4.2 导入异常

导入时需要检测：

- 文件不存在。
- 文件被占用。
- 文件编码无法识别。
- CSV 分隔符异常。
- 缺失表头。
- 重复字段名。
- 空字段名。
- 数据行列数与表头不一致。
- 字段类型声明无法识别。
- 表格类型声明无法识别。
- 分组表缺失 `groupKey` 字段。
- 二维表缺失 x 轴、y 轴或值字段。

#### 3.4.3 导出能力

- 支持导出 Excel。
- 支持导出 CSV。
- 支持导出当前表。
- 支持导出整个项目。
- 支持按表格类型执行专属导出逻辑。
- 导出前自动触发数据异常检测。
- 如果存在阻塞错误，禁止导出。
- 如果仅存在警告，允许用户确认后继续导出。

#### 3.4.4 导出要求

- 导出结果需要保持 Excel/CSV 兼容。
- 导出不得引入运行时专用格式。
- 普通表按标准表格结构导出。
- 分组表导出时需要按 group 划分区间，并保留 group 边界信息。
- 二维表导出时需要按 x 轴和 y 轴还原为可阅读的矩阵结构。
- 列表字段需要导出为稳定、可解析的文本表达，并保留元素顺序。
- 自定义数据元字段需要导出为稳定、可解析的复合字段表达，并保留子字段名与子字段值。
- 导出失败必须提供错误原因。
- 导出结果为空时必须提示。
- 导出成功后记录导出日志，包括导出范围、目标路径、耗时、问题数量。

#### 3.4.5 面向程序的导出接口

除 Excel/CSV 数据导出外，MVP 需要提供面向程序的规则与类型定义导出接口，用于让程序侧读取配置表结构约束，而不是手工同步字段含义。

面向程序的导出接口至少包含：

- 项目全局枚举定义。
- 自定义数据元定义。
- 表格类型定义。
- 表字段定义。
- 表主键和特征键定义。
- 字段类型定义。
- 引用关系定义。
- 字段校验规则。
- 导出版本号和生成时间。

该接口可以以独立元数据文件形式输出，但不改变 MVP 数据本体仍以 Excel/CSV 为主要输入输出格式的边界。

### 3.5 规则与校验模块

#### 3.5.1 规则类型

MVP 支持以下规则：

- 字段类型规则。
- 必填规则。
- 唯一规则。
- 数值范围规则。
- 枚举规则。
- 跨表引用规则。
- 重复 ID 规则。
- 空引用规则。
- 表格类型规则。
- 分组表 group 规则。
- 二维表坐标完整性规则。
- 列表字段规则。
- 自定义数据元子字段规则。
- 项目全局枚举引用规则。

#### 3.5.2 校验范围

- 支持整项目校验。
- 支持当前表校验。
- 支持选中区域校验。
- 支持导入后自动校验。
- 支持保存前可选校验。
- 支持导出前强制校验。

#### 3.5.3 校验结果分级

- Error：阻塞导出，必须修复。
- Warn：不阻塞导出，但需要用户确认。
- Info：提示性信息，用于展示建议或潜在风险。

#### 3.5.4 校验结果字段

每条校验结果必须包含：

- 严重级别。
- 规则类型。
- 表名。
- 字段名。
- 行号。
- 单元格位置。
- 当前值。
- 表格类型。
- 字段类型。
- 问题原因。
- 建议修复方式。
- 是否阻塞导出。

#### 3.5.5 项目全局枚举管理

MVP 需要提供项目全局枚举管理能力，避免不同配置表重复维护同一组枚举值。

全局枚举管理需要支持：

- 创建、编辑、删除枚举类型。
- 为枚举类型维护枚举项、显示名、说明和排序。
- 在字段规则中引用全局枚举类型。
- 在表格编辑时以下拉选择或自动补全方式快速编辑枚举值。
- 检测枚举值变更对引用字段的影响。
- 导出面向程序的枚举定义。

全局枚举定义至少包含：

- 枚举类型标识。
- 类型显示名。
- 类型说明。
- 枚举项标识。
- 枚举项显示名。
- 枚举项数值或导出值。
- 枚举项说明。
- 是否废弃。

被废弃的枚举项不应出现在新增编辑候选中，但历史数据中仍可识别并给出警告。

### 3.6 数据异常检测系统

#### 3.6.1 系统定位

数据异常检测系统是 XTable 的核心质量保障能力，负责在导入、编辑、保存、校验、导出等关键节点发现配置风险，并把问题转化为可定位、可筛选、可解释、可修复的异常报告。

#### 3.6.2 检测时机

- 导入完成后自动检测结构异常。
- 单元格编辑后增量检测当前字段相关规则。
- 保存前可执行当前表检测。
- 导出前强制执行导出范围检测。
- 用户可手动触发当前表、选中区域、整项目检测。

#### 3.6.3 结构异常检测

需要检测：

- 缺失表头。
- 重复字段名。
- 空字段名。
- 字段类型不匹配。
- 字段规则缺失。
- 非法空行。
- 表结构变化。
- 表名重复。
- 关键表缺失。
- Table 主键缺失、重复或不稳定。
- Table 特征键字段不存在或无法生成预览。
- 表格类型缺失或无法识别。
- 表格类型专属参数缺失。
- 表格类型与当前表结构不匹配。
- 自定义数据元类型缺失或无法识别。
- 自定义数据元子字段缺失、重复或类型非法。
- 自定义数据元结构复杂度超过建议阈值。
- 列表字段元素类型缺失或无法识别。
- 字段引用的全局枚举类型不存在。

#### 3.6.4 内容异常检测

需要检测：

- 重复 ID。
- 必填为空。
- 整数或浮点数格式非法。
- 布尔值格式非法。
- 枚举值不在候选范围内。
- 数值超出最小值或最大值。
- 引用字段为空。
- 引用目标不存在。
- 单元格包含不可见非法字符。
- 分组表存在空 `groupKey`。
- 分组表存在无法归属 group 的数据行。
- 二维表存在重复坐标。
- 二维表存在缺失坐标。
- 二维表存在超出 x 轴或 y 轴范围的数据。
- 列表字段存在非法元素。
- 列表字段长度超出规则范围。
- 列表字段嵌套深度超出限制。
- 自定义数据元子字段必填为空。
- 自定义数据元子字段类型不匹配。
- 自定义数据元实例数量过大，已不适合作为嵌入式字段维护。
- 字段值引用已废弃枚举项。

#### 3.6.5 跨表关系异常检测

需要检测：

- 引用链断裂。
- 引用目标重复。
- 引用目标表不存在。
- 引用目标字段不存在。
- 循环依赖。
- 关键配置表缺失。

#### 3.6.6 导入导出异常检测

需要检测：

- 编码问题。
- 分隔符异常。
- 文件被占用。
- 目标路径不存在。
- 保存失败。
- 导出结果为空。
- 导出文件无法写入。
- 导出前存在阻塞错误。
- 分组表导出时 group 边界生成失败。
- 二维表导出时矩阵还原失败。
- 列表字段导出表达式生成失败。
- 自定义数据元导出表达式生成失败。
- 面向程序的枚举或类型定义导出失败。

#### 3.6.7 异常报告视图

异常报告视图需要支持：

- 按严重级别筛选。
- 按表筛选。
- 按表格类型筛选。
- 按字段筛选。
- 按字段类型筛选。
- 按规则类型筛选。
- 按关键词搜索。
- 点击异常项跳转到源单元格。
- 展示问题原因和建议修复方式。
- 导出或复制异常摘要，便于反馈给程序或工具开发者。

### 3.7 日志系统

#### 3.7.1 系统定位

日志系统用于记录用户操作、系统状态、数据变更和异常诊断信息，帮助团队追踪配置修改历史、定位工具问题、复现异常场景。MVP 日志为本地日志，不包含服务端审计平台。

#### 3.7.2 日志类型

日志系统包含四类日志：

- 用户操作日志：记录打开项目、导入、编辑、批量修改、校验、导出、保存、撤销、重做等行为。
- 系统日志：记录启动、关闭、文件读写、解析失败、性能耗时、异常堆栈等信息。
- 数据变更日志：记录表、行、字段、旧值、新值、时间、操作者、会话 ID。
- 异常日志：记录导入异常、校验异常、保存异常、导出异常、程序异常等诊断信息。

#### 3.7.3 日志级别

日志级别从低到高为：

- Debug：开发调试信息，默认不展示。
- Info：普通操作和状态信息，默认展示。
- Warn：非阻塞风险或可恢复异常，默认展示。
- Error：阻塞操作或需要用户处理的问题，默认展示。
- Fatal：导致程序无法继续执行的严重异常，默认展示并生成诊断信息。

#### 3.7.4 日志字段

每条日志至少包含：

- 时间。
- 日志级别。
- 日志类型。
- 模块名。
- 操作者。
- 会话 ID。
- 操作对象。
- 表格类型。
- 简短描述。
- 详细上下文。
- 错误堆栈或诊断信息。

数据变更日志还需要包含：

- 表名。
- 行号。
- 字段名。
- 旧值。
- 新值。
- 操作类型。

#### 3.7.5 日志面板

UI 日志面板需要支持：

- 按时间筛选。
- 按级别筛选。
- 按模块筛选。
- 按日志类型筛选。
- 按关键词搜索。
- 复制单条日志。
- 复制诊断摘要。
- 清空当前视图过滤条件。

#### 3.7.6 日志保留

- 本地日志默认保留最近 30 天。
- 日志保留天数可在项目设置中调整。
- 日志文件需要按日期或大小滚动。
- 超过保留策略的旧日志可自动清理。
- 日志目录需要与正式表数据分离，便于版本工具忽略。

#### 3.7.7 诊断信息

关键错误需要生成可复制诊断信息，至少包含：

- 应用版本。
- 操作系统。
- 项目路径。
- 当前表名。
- 操作者。
- 会话 ID。
- 错误时间。
- 错误摘要。
- 相关日志片段。
- 异常堆栈。

### 3.8 权限与协作边界模块

#### 3.8.1 MVP 协作边界

MVP 不实现：

- 登录账号。
- 角色权限。
- 实时多人编辑。
- 云端同步。
- 内置审批流程。
- 发布审批状态。

#### 3.8.2 本地操作者

- 支持设置本地操作者名称。
- 操作者名称用于用户操作日志和数据变更日志。
- 未设置操作者名称时使用系统用户名或默认名称。

#### 3.8.3 文件协作风险

需要检测：

- 文件被外部修改。
- 文件保存冲突。
- 只读文件。
- 文件被占用。
- 版本工具锁定状态。

当检测到风险时，编辑器需要明确提示风险类型，并阻止静默覆盖。

#### 3.8.4 后续扩展方向

后续版本可扩展：

- 审核流。
- 多人协作。
- 云端项目。
- 发布管线。
- 权限控制。
- 配置版本对比与回滚。

这些能力不进入 MVP 范围。

## 4. 非功能需求

### 4.1 易用性

- 普通策划应能在 30 分钟内完成打开项目、定位表、编辑、校验、导出的基础流程。
- 高频功能需要有快捷键或明显入口。
- 错误提示必须使用业务可理解语言，避免只展示技术异常。
- 功能侧边栏标签切换需要直观稳定，用户能明确知道当前处于 Table、Enum 或 Meta 哪个工作上下文。
- 新建、导入、导出等信息收集弹窗需要清晰展示必填项、默认值、校验错误和确认结果。

### 4.2 性能

- 打开中等规模项目时应有加载进度反馈。
- 大表滚动、选择、编辑不应出现明显卡顿。
- 校验耗时超过 1 秒时需要展示进度或状态。
- 导入、导出、整项目校验需要记录耗时日志。

### 4.3 稳定性

- 文件读写失败不得导致应用崩溃。
- 单张表解析失败不得阻止用户查看其他可用表。
- 批量操作失败时需要说明已完成和未完成范围。
- 异常退出后应尽量提供恢复未保存内容的能力。

### 4.4 可维护性

- UI、项目文件、数据编辑、导入导出、规则校验、异常检测、日志系统应按模块解耦。
- 编辑器所有可见 UI 组件、弹窗、按钮、面板、状态提示和主题适配都应由 UI 模块统一提供。
- 校验规则需要有统一结果结构，便于 UI 展示和导出前阻塞判断。
- 日志接口需要统一，避免各模块自行拼接不一致日志。
- 表格类型需要通过统一扩展接口接入，新增表格类型时不得破坏普通表、分组表、二维表的已有行为。
- 字段类型、自定义数据元、列表字段和全局枚举需要通过统一类型系统接入，便于编辑器、校验器和程序导出接口复用同一份类型定义。

## 5. 验收标准

### 5.1 项目与导入验收

- 用户能创建并打开本地配置项目。
- 用户能导入包含多张配置表的 Excel/CSV 文件。
- 导入后能在项目资源管理器中浏览、搜索、切换配置表。
- 导入异常能生成结构异常报告。

### 5.2 UI 与主题验收

- 主界面包含顶部工具栏、中间操作区、底部状态栏。
- 中间操作区最左侧为功能侧边栏，侧边栏至少包含 Table、Enum、Meta 标签。
- 用户点击 Table、Enum、Meta 标签时，右侧功能窗口能切换到对应主界面。
- 顶部工具栏能承载新建、导入、导出、保存、校验、撤销、重做、主题切换等常用入口。
- 底部状态栏能展示当前项目、当前对象、保存状态、校验状态、后台任务和问题数量。
- 底部状态栏的问题按钮能展开和收起底部问题报告抽屉。
- 发生高风险问题时，底部问题报告抽屉能自动弹出并定位到对应问题。
- UI 模块能支持功能窗口、消息提示弹窗、信息收集弹窗、图标按钮、文本按钮、面板、基础表单与列表组件。
- 编辑器能在 Dark 和 Light 主题之间切换，切换后所有可见 UI 立即刷新。
- 主窗口、侧边栏、功能窗口、工具栏、状态栏、弹窗、按钮、表格、日志和异常报告在两套主题下都可读、可辨、可操作。
- UI 模块能为窗口切换、抽屉展开收起、弹窗、按钮状态、列表展开折叠和主题切换提供统一、简洁、高效的过渡动画。

### 5.3 编辑验收

- 用户能完成单元格编辑、多选区域编辑、复制粘贴、拖拽填充。
- 用户能插入和删除行列。
- 用户能使用筛选、排序、查找替换、批量编辑。
- 用户能撤销和重做编辑操作。
- 用户能创建或打开普通表、分组表、二维表。
- 用户能为 Table 设置主键和特征键。
- 其他表引用该 Table 时，引用字段保存主键值，并展示特征键预览。
- 用户能为分组表设置 `groupKey`，并在编辑区识别不同 group。
- 用户能为二维表设置 x 轴、y 轴和值字段，并编辑 `x * y` 个值。
- 用户能创建自定义数据元，并将其作为字段类型使用。
- 当数据元结构过于复杂或数据量过大时，编辑器能提示用户改为独立配置表。
- 用户能将 Meta 升级为 Table，编辑器能自动补全相关表引用，并替换对应字段类型。
- 用户能创建列表字段，并在列表中编辑基础类型、枚举、引用或自定义数据元。
- 用户能在项目全局枚举管理中创建、编辑、废弃枚举项，并在表格字段中快速选择枚举值。

### 5.4 校验与异常检测验收

- 系统能检测字段类型错误。
- 系统能检测必填为空。
- 系统能检测唯一字段重复。
- 系统能检测主键缺失、重复或不稳定。
- 系统能检测特征键字段不存在或无法生成预览。
- 系统能检测数值范围越界。
- 系统能检测枚举越界。
- 系统能检测跨表引用不存在。
- 系统能检测重复 ID 和空引用。
- 系统能检测表格类型缺失或无法识别。
- 系统能检测分组表缺失 `groupKey`、空 `groupKey`、无法归组数据。
- 系统能检测二维表缺失 x 轴/y 轴/值字段、重复坐标、缺失坐标、坐标越界。
- 系统能检测列表字段元素类型错误、空元素、长度越界和嵌套深度越界。
- 系统能检测自定义数据元子字段缺失、类型错误和必填为空。
- 系统能检测自定义数据元结构复杂度或实例数量超过建议阈值。
- 系统能检测字段引用不存在的全局枚举类型或已废弃枚举项。
- 异常报告能定位到表、字段、行、单元格。
- 异常报告能说明问题原因和建议修复方式。

### 5.5 导出验收

- 用户能导出当前表为 Excel/CSV。
- 用户能导出整个项目为 Excel/CSV。
- 分组表导出后能按 group 划分区间，并保留可识别的 group 边界。
- 二维表导出后能按 x 轴和 y 轴还原为矩阵结构。
- 列表字段和自定义数据元字段能导出为稳定、可解析的表达。
- 程序侧能通过独立导出接口获取全局枚举、自定义数据元、字段类型、表结构和校验规则定义。
- 导出前会自动执行异常检测。
- 存在 Error 级问题时禁止导出。
- 仅存在 Warn 级问题时，用户确认后可继续导出。
- 导出成功和失败都需要记录日志。

### 5.6 日志验收

- 系统能记录打开项目、导入、编辑、批量修改、校验、导出、保存、撤销、重做。
- 系统能记录启动、关闭、文件读写、解析失败、性能耗时、异常堆栈。
- 系统能记录数据变更的表、行、字段、旧值、新值、时间、操作者、会话 ID。
- UI 日志面板能按时间、级别、模块、类型、关键词筛选。
- 关键错误能生成可复制诊断信息。
- 日志能按保留策略滚动和清理。

### 5.7 版本工具友好验收

- 项目规则和配置文件可被版本工具追踪。
- 日志、缓存、临时恢复文件可被版本工具忽略。
- 修改单张表时不应导致大量无关文件变化。
- 外部文件变更、只读、占用、保存冲突能被检测并提示。

```text
  tables/              # 表数据
  rules/               # 字段规则、引用关系
  enums/               # 项目全局枚举定义
  types/               # 自定义数据元和字段类型定义
  settings/            # 项目设置和本地偏好
  logs/                # 本地日志，建议版本工具忽略
  cache/               # 缓存，建议版本工具忽略
  recovery/            # 异常恢复数据，建议版本工具忽略
```

推荐忽略：

```text
logs/
cache/
recovery/
*.tmp
*.lock
```

## 7. 默认假设

- MVP 以 Excel/CSV 为主要输入输出格式。
- MVP 支持普通表、分组表、二维表三类表格类型，并要求表格类型体系可扩展。
- MVP 支持项目全局枚举管理、自定义数据元、列表字段，并允许列表字段嵌套基础类型、枚举、引用和自定义数据元。
- MVP UI 需要完整支持 Dark 和 Light 两套主题，并由 UI 模块统一提供组件、弹窗、按钮、功能窗口和状态展示能力。
- 面向程序的导出接口用于导出元数据和类型定义，不改变 Excel/CSV 作为数据本体导入导出的边界。
- 完整日志系统在第一版定义为本地日志、操作日志、异常日志和数据变更日志。
- 数据异常检测系统是内置校验与诊断能力，不要求第一版支持用户自定义脚本规则。
- 第一版优先本地桌面工作流，不引入服务器依赖。
- 当前需求文档作为新项目 PRD，可在技术方案确定后继续拆分为实现计划。
