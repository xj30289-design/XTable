# XTable 自定义数据元规格

## 1. 定位

自定义数据元，简称 Meta，用于表达可复用的复合字段结构。Meta 适合少量结构化数据复用，例如条件、奖励项、坐标、属性加成、消耗项。

Meta 与 Table 的区别：

- Meta 是嵌入式复合值，通常作为字段类型使用。
- Table 是独立配置表，拥有行、主键、引用关系和独立导入导出边界。
- 当 Meta 结构复杂、嵌套过深、引用过多或实例量过大时，应提示升级为 Table。

## 2. Meta 类型结构

Meta 类型至少包含：

| 属性 | 必填 | 说明 |
| --- | --- | --- |
| `meta_id` | 是 | 项目内唯一类型 ID |
| `display_name` | 是 | 用户可读名称 |
| `description` | 否 | 类型说明 |
| `fields` | 是 | 子字段列表 |
| `export_name` | 否 | 面向程序的导出名称 |
| `max_depth` | 是 | 最大嵌套深度，MVP 默认 3 |
| `complexity_threshold` | 否 | 复杂度提示阈值 |
| `references` | 否 | 引用该 Meta 的字段列表 |
| `created_at` | 否 | 创建时间 |
| `updated_at` | 否 | 最近更新时间 |

Meta 类型规则：

- `meta_id` 必须稳定。
- 子字段顺序必须稳定。
- 子字段可以使用基础字段类型、枚举字段、引用字段、列表字段或其他 Meta 字段。
- MVP 默认最大嵌套深度为 3。

## 3. Meta 子字段结构

Meta 子字段与 Table 字段使用同一套字段定义、字段类型和字段能力。除作用域从“表内字段”变为“Meta 内子字段”外，Meta 子字段在编辑、默认值、必填、唯一、只读、范围、导入解析、导出表达、复制粘贴、排序筛选和校验规则上应与 Table 字段保持一致。

Meta 子字段至少包含：

| 属性 | 必填 | 说明 |
| --- | --- | --- |
| `field_id` | 是 | Meta 内唯一字段 ID |
| `name` | 是 | 面向配置和导出的字段名 |
| `display_name` | 是 | 用户可读名称 |
| `description` | 否 | 字段说明 |
| `field_type` | 是 | 字段类型标识 |
| `default_value` | 否 | 默认值 |
| `required` | 是 | 是否必填 |
| `unique` | 否 | 是否在当前 Meta 实例或列表上下文中要求唯一 |
| `readonly` | 否 | 是否只读 |
| `range` | 否 | 数值范围、长度范围或元素数量范围 |
| `export_name` | 否 | 面向程序的导出字段名 |
| `validation_rules` | 否 | 附加校验规则 |

子字段规则：

- 同一 Meta 内子字段名不得重复。
- 必填子字段为空生成 Error。
- 子字段类型必须是字段类型系统支持的类型。
- 子字段如果引用 Enum、Table 或其他 Meta，必须参与引用影响分析。
- 子字段支持 [字段类型规格](./field-types.md) 中定义的全部 MVP 字段类型：`string`、`int`、`float`、`bool`、`enum`、`id`、`reference`、`list`、`meta`、`json`。
- 子字段的 UI 编辑器、默认值、空值、导入解析、导出表达、复制粘贴、排序筛选、校验规则和错误提示必须复用对应 Table 字段类型行为。
- 当 Table 字段能力扩展时，Meta 子字段默认同步获得该能力；如果某项能力不适用于 Meta，必须在本规格中明确列为例外。

## 4. 嵌套规则

- Meta 可以嵌套 Meta。
- List 可以包含 Meta。
- Meta 可以包含 List。
- MVP 默认最大嵌套深度为 3。
- 超过最大嵌套深度生成 Error。
- 接近复杂度阈值时生成 Warn，提示考虑升级为 Table。

复杂度建议指标：

- 嵌套深度。
- 子字段数量。
- 引用字段数量。
- 列表字段数量。
- 单张表中 Meta 实例数量。

## 5. 编辑行为

Meta 功能窗口必须支持：

- Meta 类型列表。
- Meta 类型创建、重命名、描述编辑。
- 子字段新增、删除、排序、复制。
- 子字段类型、默认值、必填、导出名配置。
- 引用关系查看。
- 复杂度提示。
- Meta 升级为 Table 的入口。

Meta 字段编辑器必须支持：

- 展开式或弹出式结构化编辑。
- 必填子字段标记。
- 子字段错误定位。
- 复制和粘贴整个 Meta 值。

## 6. 导入导出表达

导入：

- 支持从稳定文本表达解析 Meta 值。
- 支持从结构化列映射解析 Meta 值。
- 子字段缺失按默认值和必填规则处理。
- 未识别子字段生成 Warn 或 Error，MVP 默认 Warn。

导出：

- 导出为稳定、可解析、保留子字段名与子字段值的复合表达。
- 子字段顺序必须稳定。
- 空可选子字段可以省略，但必须保证重新导入后含义一致。
- 面向程序的定义导出必须包含 Meta 类型、子字段、字段类型和导出名。

## 7. Meta 升级为 Table

Meta 升级为 Table 用于处理结构复杂或数据量较大的嵌入式数据。

必须定义：

- 触发入口：Meta 功能窗口中的升级操作，以及复杂度提示中的快捷入口。
- 复杂度提示条件：嵌套深度过深、字段数量过多、引用过多、实例数量过大。
- 变更预览：展示将创建的新 Table、字段列表、引用替换范围。
- 新 Table 结构生成：基于 Meta 子字段生成普通表结构。
- 原字段引用替换：原本引用该 Meta 的字段替换为引用新 Table 的引用字段。
- 冲突检测：表 ID 冲突、字段名冲突、引用目标冲突、数据迁移冲突。
- 回退方案：升级前生成可恢复变更记录，失败时回滚结构和字段引用。
- 日志记录：记录升级发起人、时间、原 Meta、新 Table、影响字段和结果。

## 8. 校验规则

Meta 相关校验包括：

- Meta 类型不存在：Error。
- 子字段不存在：Error。
- 子字段类型不合法：Error。
- 必填子字段为空：Error。
- 嵌套深度超过限制：Error。
- 复杂度超过建议阈值：Warn。
- 引用的 Enum、Table 或 Meta 不存在：Error。
- 导出表达无法稳定生成：Error。

## 9. 日志事件

必须记录：

- 创建、修改、删除 Meta 类型。
- 新增、删除、修改、排序子字段。
- 修改 Meta 字段值。
- 复杂度提示。
- Meta 升级为 Table。
- Meta 导入导出失败。

## 10. 验收标准

- 用户能创建 Meta 类型并配置子字段。
- 字段能使用 Meta 类型。
- Meta 值能被编辑、复制、粘贴、导入和导出。
- 嵌套深度和复杂度能被检测。
- Meta 升级为 Table 有预览、冲突提示和回退方案。
